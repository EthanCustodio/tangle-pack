# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Project Is

`tanglepack` is a Python library for computing and visualizing **heteroclinic/homoclinic tangles** — the stable and unstable manifolds of saddle fixed points in 2D discrete dynamical systems (area-preserving maps). The core scientific workflow is: define a map → find a fixed point → initialize manifolds → grow them iteratively → detect intersections → extract bridges and resonance zones.

There is currently no GUI frontend: the old Dash dashboard (`tanglepack_webdash`) and PySide6 GUI (`tanglepack_gui`) were removed in July 2026 (recoverable from git history) and a new GUI will be built from scratch later. The library is used through scripts, notebooks, and the `TangleWorkbench`/`TangleSession` APIs.

## Fundamental Invariant — Which Manifolds Can Intersect

This is a hard physical law of the system, not a convention, and it must inform every piece of intersection/bridge logic:

- **Two unstable manifolds can never intersect each other.** Two stable manifolds can never intersect each other. This holds whether the manifolds belong to the same fixed point or to different fixed points.
- **Only an unstable manifold can cross a stable manifold** (homoclinic when they share a fixed point, heteroclinic when they belong to different fixed points).

Why: a point on a stable manifold converges to that manifold's fixed point under forward iteration; a point on an unstable manifold converges to its fixed point under backward iteration. A shared point of two stable manifolds would have to converge forward to *both* fixed points at once (and a shared point of two unstable manifolds would have to converge backward to both) — impossible. The same uniqueness argument forbids a manifold from crossing itself.

**Implication for the code:** a same-stability pair (u×u or s×s) is *always* a numerical artifact — two near-parallel polygonal approximations straddling near a tangency, not a real crossing — and must never be treated as a legitimate geometric case to model. Since WP10 the `Tangle` never forms one: it keeps one rtree per stability and queries a segment only against the OTHER stability's index, so `_intersecting_segments` holds u×s pairs only (asserted). The same holds for a polyline crossing ITSELF (a Z-kink of one manifold) or a blast's image bridge crossing another same-stability curve: the Tangle index never tested those, and since 2026-10-07 `numerics/diagnostics.py` reports them as polygon ARTIFACTS of under-resolution (WARNING in the tangle box, INFO outside) -- a flag to refine, never a crossing.

## Area Preservation

These maps are **area-preserving**: mapping any region forward (or backward) produces a region of exactly the same area. This is a fundamental property of the system, not an approximation.

A consequence used by the topological layer: for a HOMOCLINIC intersection point, the product of its stable and unstable canonical distances behaves like a preserved area (one forward iterate scales the unstable cdist up by the per-step eigenvalue factor and the stable cdist down by the same factor, so the product is unchanged along an iterate chain). On a heteroclinic link `W^u(A) x W^s(B)` each side scales by its OWN saddle (the unstable cdist by `beta_A`, the stable by `1/beta_B`), so the product scales by `beta_A / beta_B` per step (NUM-20, WP10b: the iterate inference always did this; two laws had read A's factor for both sides). Note, however, that two *different* iterate chains generally have *different* such products — equal products do not imply two points are on the same chain, so do not use the product alone to decide chain membership. Compare the stable and unstable canonical distances individually (a collision on both means the same point) when you need to know whether two intersections are iterates.

## The pipeline, stage by stage

`docs/design_note.md` states each stage's definition, the functions that implement it and every decision behind it (its section I indexes the decision ids); `.refactor/decisions.md` keeps the author's decisions and their history. One paragraph per stage here.

**Global rules.** The topology reads the iterate table (`Trellis.iterate`) and scales a canonical distance only through `Trellis.image_cdist` when the table has no link; it never calls the map, except `Arrangement.image_of` (a verification), `diagnostics.measured_sides` (a resolution flag, on the default `Trellis.punch_holes(diagnose=True)` path) and `plotting.hole_point` (drawing). Geometric readings are flags and never decide. A class exists iff a computed bridge spans it or the word of an existing class names it. The walk constraints are not proved complete, so a surviving tie is "ambiguous", never broken by order. Blasting or growing further may change the topology: that is discovery, not failure (design note §A.0).

**Stage 0, manifolds.** Each branch is a polyline with canonical distance non-decreasing along it, grown one map step at a time by `ManifoldMachine.iterate_manifold` with refinement at `area_cutoff` (chord deviation `h = 1.5 A / L`, default 1e-7); one fundamental segment per chain of `k_value` pieces (`ManifoldInitializer.construct_kevin_way`). `FixedPoint` is the one source of branch bookkeeping: `advance_key`, `per_step_beta`, `branch_cycle`, `preserves_orientation` (the sign of the single-step Jacobian determinant). Existing images are merged chain by chain (`ManifoldMachine._image_chains`); every top-level growth call raises `PointBudgetExceeded` before the map call that would exceed its budget (design note §A.1).

**Stage 1, the crossing set N.** One procedure on every path (`TangleWorkbench.compute_intersections`, `Tangle.resolve_crossings`): each unstable segment is queried against the stable index only, each hit is deduplicated by branch keys and both cdists to the relative `DEDUP_RTOL`, bracketed, and registered in unstable-cdist order (ids are reproducible). Every detection is registered, but N is the RESOLVED subset `IntersectionRegistry.resolved_ids(threshold)`: `resolution_ratio` at least `resolution_ratio_threshold` (3; the law-case minimum is 3.04) and in no run of detections closer than their chord deviation (`run_separation`). An unresolved detection is no point of N: no bridge ends at it, no link touches it, and `report_resolution` names it with the remedy "refine". A periodic point is ONE synthetic anchor at cdist (0, 0) on every branch attached to it; an inversion point has two stable and two unstable branches, the left of 0.0 being the right of 0.1. Bridges are cut at the exact crossings of N (`Tangle.create_bridges`) and asserted on registration (`TangleWorkbench._register_bridge`) (design note §A.2).

**Stage 2, the iterate table.** A partial bijection `N -> N` built by `infer_iterates`: `y = M(x)` iff `y` is on the advanced branches, both brackets meet `x`'s carried one step by `stretch_param`, uniquely, and the real map confirms it in one batched call; both cdists are compared individually, never their product. A source with several candidate images, or an image claimed by several sources, goes to `registry.unresolved_links` and is never linked. Inference runs in `compute_intersections`, in every `iterate_bridge` and at the end of every `blast_zone`; the topology only looks links up (design note §A.3).

**Stage 3, the strong pip and the trellis of the pip.** A crossing q0 is a strong pip iff no crossing of its fixed point, mapped backward onto its stable branch, lands strictly inside the box `(0, c_s(q0)) x (0, c_u(q0))` (`is_strong_pip`; unresolved detections disqualify nothing; candidates are classified on first read). Choosing it CUTS the trellis to `T(q0) = (W^u[P, f^m(q0)], W^s[P, q0])` in one place, `Trellis.cut_at_pip_orbit`: stable branch j at c_s(f^j q0), unstable branches at the `k_value` deepest orbit points up to `m`, the registered `+1` chain of the chosen pip through crossings of N (`BlastResult.pip_depth`). An unresolved orbit point therefore freezes `T(q0)` until refinement resolves it, and `blast_zone` never drops a child on that orbit by `min_separation`. A missing orbit point is placed by `image_cdist` with one WARNING. A crossing past a cut leaves every branch and the arc across it joins two bridges (`Bridge.joined`; resolve bridges through `Trellis.bridge_between`). At an anchor an arc of `u(o,b)` meets `s(o,b)` (`Trellis.stable_key_at`). A trellis holds a crossing only when both its branches are selected (design note §A.4).

**Stage 4, pseudoneighbor pairs.** Consecutive crossings `x, x'` on a stable branch of `T(q0)` are a pair iff neither open interval, stable or unstable, holds a point of X; both are tested by one function, `_interval_is_clear(..., stability, ...)`, landing each crossing's orbit by table lookup first, else by scaling, with a branch return costing `beta^k_value`. References lie in the window `(c_s(f^k q0), c_s(q0)]` on the pip's branch; `extend_pseudoneighbor_trajectories` records their table iterates inside `T(q0)`, forward ones included (they are real pairs, never holed). A heteroclinic pair (two crossings of `W^u(A)` on B's stable branch) is a pair of B's tangle, tested with A's cycle and beta; it exists only on a trellis holding both tangles (design note §A.5).

**Stage 5, holes.** Holes are combinatorial: `Hole(near_intersection_id, pair, bridge_side, bounding_ids, openings, iterate, origin)`. `punch_holes` punches the REFERENCE pairs only, on their `bridge_side` read off the crossing signs; holes propagate BACKWARD only, on every orbit (a forward iterate never gets a hole). `propagate_reference_holes` moves the reference bridge's two crossing ids by `Trellis.image_cdist`, finds the container by a bisect over the branch's crossing order (`_containing_bridge`) and holes the WHOLE container, carrying the side (`side_after`) until a container repeats or none exists; a scaled span end within `SCALING_RTOL` of a crossing is one WARNING. The signs decide the openings (`_hole_openings`: the outward half iff `(crossing_sign > 0) == (bridge_side == "left")`). The geometric readings live in `topology/diagnostics.py` (`geometry_flags`, `bridge_row_diagnosis`, `measured_sides`, `side_source`) and only flag under-resolution (design note §A.6).

**Stage 6, the stable partition.** `partition_stable_manifold` cuts each stable branch at every hole bridge's endpoints (plus the anchor and the outermost crossing); an interval is open at an end iff a hole opens that half, a point excluded on both sides is a closed singleton, and a branch with no crossing past its anchor is one element `[anchor, end]`. Rows come from the signs (`row_of_end`: `row(first) = left iff sign > 0`, `row(second) = left iff sign < 0`). Ownership is exact: boundaries are registry floats and no absolute cdist slack is read. `PartitionFamily.owner_at_end` is the one reader of a bridge end's element on its row; `owner_of_intersection` reads any side of a named branch (design note §A.7).

**Stage 7, bridge classes and inertness.** `bridge_classes` returns the EVIDENCE table: each bridge's class is the unordered pair of the elements its ends sit in on their rows (`owner_at_end`), oriented anchor outward (`anchor_outward_key`); a loop folds FORWARD into the class of its image-chain parent (`_image_chain`, one parent per pair, asserted), and a loop no chain reaches is an orphan, never lettered. The table is grouped by tangle (outermost fixed point first) and, within a group, by smallest member first-crossing unstable cdist. The ALPHABET is its restriction to the minimal trellis (`MinimalTrellis.alphabet`). A class is INERT iff it is transient in the graph of the class-level words (`inert_classes`); `BridgeClassEntry.inert` is None until `symbolic_dynamics` sets it. Active classes are lettered `a..t, aa, ...` by the session's `BridgeAlphabet` keyed by `Topology.identity` (the bounding crossings of the two elements), inert ones `u..z, uu, ...`, both from `letter` (design note §A.8).

**Stage 8, the minimal trellis.** `minimal_trellis` keeps every hole bridge and maps every one EXCEPT a bridge carrying a zeroth (reference) hole, whose word is empty: the bridges tiling a mapped bridge's first image (`image_chain`) are kept too. A pair no `Bridge` spans is manifold never computed (`Trellis.is_computed_arc`), skipped with a WARNING. The stable manifold is kept whole, and the arrangement is sparse: an absent unstable ray is an absent wall (design note §A.8b).

**Stage 8, the word of a class.** The word of a class is its freely reduced image itinerary, and the shortest walk of the dual graph IS that word (`shortest_walks`): face, unified node, face, from the stable nodes the landing span `f(X)` meets (`land_element`) to those `f(Y)` meets, crossing the stable manifold only in the window, recording both sides of each crossing. A class with a member lobe takes the walk whose closed curve holds exactly the images of the markers the lobe holds (`lobe_image_markers`, `holds_markers`); the decided walks of earlier classes on disjoint unstable branches are walls (`walk_chords`, `DualGraph.chords_cross`). A search is "resolved", "ambiguous" or "unresolved" with one of six `WalkReason`s ("unreachable", "no_start_node", "no_goal_node", "no_admissible_walk", "truncated", "span_meets_no_node"); member lobes disagreeing on a marker raise `MembersDisagree`; "trivial" means an empty class word. Singletons read their member's registered chain (`trellis_itinerary`). The alphabet is closed under the word map, a pair no computed bridge spans being a class flagged "no computed bridge yet". `free_reduce` cancels `c c^-1` in every class-level word; `translate_itinerary` stays unreduced. Registered images are only evidence, compared at word level by `diagnostics.verify_words` ("stable end" and "order flip" give no verdict, "walk" counts against `is_reliable`). k=10 reads `a -> a u^-1 a^-1` (design note §A.8c).

**Stage 8, the iterated partition and the refined level.** `IteratedHomotopyPartition.from_minimal` cuts each branch further at every crossing of the kept image bridges by the empty-stretch rule: a hole's stretch, and the base and chords of its image lobe, are empty; chords pair in STABLE order on every branch; an image crossing belongs to the element away from the empty stretch it abuts. A chain crossing a branch an odd number of times is recorded in `incomplete_footprints` (data, one INFO). `refine` splits a class by its occurrences in all words (`a_1, a_2, ...`); by Theorem T (members share their `P1`-level reduced itinerary, a law on the law cases and the blast series) the refined word is every member's word and the refined matrix is an in-splitting of the class matrix (design note §A.8d).

**Stage 9, the transition matrix.** `SymbolicDynamics.transition_matrix` counts, over the active classes, the tokens of each freely reduced word; refined by default (k=10: `[[1,1],[1,1]]`). Inert classes are no nodes of `SymbolicDynamics.transition_graph` or the matrix; no spectral radius is shown (design note §A.9).

**Stage 10, recompute and blasting.** The topology is a pure function of the registry, the bridges and the pips: `TangleSession.topology` holds one `Topology` per generation, selection and pips, and any growth or blast recomputes it. Grow, blast and recompute commute: a blast's image curves are computed manifold the workbench keeps and re-indexes. `blast_zone` iterates the bridges whose innermost zone it is; any failure to map a bridge propagates; `max_points` is a resumable stop between iterations; a `min_separation` drop is remembered on the bridge (`Bridge.dropped_at`) and skipped by later calls unless they pass a smaller separation or None, the guard testing every curve the workbench holds, so `n` single-iteration blasts equal one `n`-iteration blast; `min_separation="resolution"` ties the separation to the cutoff (`1e-5 * (area_cutoff / 1e-7) ** (2/3)`, the chord deviation's scaling). The depth `pip_depth` is non-decreasing over a blast series. A stable trim is a view and `ResonanceZone.restore` never shortens a grown branch (design note §A.10).

**Session and API.** `TangleSession` holds the workbench, caches one `Topology` per (generation, selection, pips) and remembers pips and letters; it has no stage fan-outs (`classify_strong_pips` still runs per fixed point, for pip memory) and no plot delegates (`cartoon_zones` and `plot_resonance_zones` are in `loom/cartoon.py`, `cartoon_enclosures` in `topology/plotting.py`). A chosen pip is remembered as a crossing and restored on every rebuilt trellis; `resonance_zone` adopts its pip only when it is a candidate; a remembered pip that stops being one is never replaced, `topology()` raises, and `forget_strong_pip` is the remedy. One resonance zone per fixed point. Fixed points are constructed outermost first, so the period-1 saddle is `A` and tangle 0 (design note §A.11).

## Core Library Architecture (`src/tanglepack/`)

Three subpackages plus examples. **Dependency rule: `numerics` and `topology` never import `loom`** (loom sits on top and weaves the other two together).

- `numerics/` — the numerical engine: maps, fixed points, manifold growth, crossing detection, bridges, the intersection registry.
- `topology/` — combinatorial structures over the registry: the `Trellis` snapshot, strong pips, pseudoneighbors, holes, the stable partition, the planar `Arrangement` of regions, bridge classes, the minimal trellis and dual graph, and the symbolic dynamics (element names, dual-graph walks, words).
- `loom/` — cross-layer algorithms that read topology and act on numerics: `TangleSession`, `Topology`, resonance zones, blasting, the zone cartoon.
- `examples/henon.py` — the one Hénon map definition (`henon_map(k, b)`, `henon_map_inverse`, `henon_jacobian`, `saddle_guesses`) used by tests and scripts (the notebooks still carry their own copies); `examples/henon_cases.py` — the shared higher-period recipes `build_period3()` / `build_nested()` / `build_heteroclinic()` (period 3 at 16 / 10 steps: four `W^u(p3) x W^s(p1)` crossings, two in the trellis) → `TangleBuild` (session, fixed points outermost first — constructed in that order, so p1 is `A` and tangle 0 —, pips, title, slug; each ends at `session.topology()`, the pips carried by the session through every blast, no repin), used by the figure scripts and `tests/regression/test_nested_own_blast.py`; a nested build's slug encodes non-default blast counts (nested_p1_p3_outer5_inner1; the defaults keep nested_p1_p3 / heteroclinic_p1_p3). `build_inversion()` is the k=4 inversion law-case recipe (11 / 11 steps at 1e-5, zone at f(q0); it raises when f(q0) is not registered, 8 steps); every period-3 build has its own slug (p3_u16_blast8). Period 3 at 13 unstable steps is closed up to 5 blasts (`a -> b -> c -> a u^-1 v^-1`, 5 classes, no image bridges); at 6 blasts (or at 15 unstable steps) the reference switches (8 -> 42 holes) and the alphabet plateaus at 23 seed / 43 closed classes, every class walks and the words are reliable (measured to 20 blasts); the pairs no computed bridge spans are flagged classes. The default stays at 13 steps, unblasted. Nested resolves every class at one outer blast; two make every outer class walk.

**Symbolic-itinerary figures.** `scripts/symbolic_figures.py` `draw_panels` writes six panels per case into `figures/henon_symbolic_itineraries/<slug>/` — `trellis`, `partitions`, `cartoon`, `itineraries`, `transitions`, `transitions_refined` — each as `.png`, `.svg` and `.fig.pickle` (networkx's curved edge labels are frozen into plain `Text` before pickling). The cartoon panel is `shape="circle"`. The trellis panel draws ONLY the minimal trellis's bridges (`plot_bridges_by_class(..., bridge_ids=minimal.kept_bridge_ids)`): every blast child is a class member, so an unfiltered plot grows with each blast even though the minimal trellis does not (nested: 16 kept bridges from 2 to 5 outer blasts while the trellis goes 38 -> 72).

The entry point for programmatic use is `TangleSession` (a facade over one `TangleWorkbench`, caching one `Trellis` per fixed-point selection and delegating unknown attributes to the workbench):

```python
import numpy as np, tanglepack
from tanglepack.examples.henon import henon_map, henon_map_inverse, henon_jacobian, saddle_guesses

session = tanglepack.TangleSession(henon_map(10), henon_map_inverse(10), henon_jacobian(10),
                                   area_cutoff=1e-4)   # default 1e-7 (converged, ~10x the points); also max_points_per_step (2,000,000; None = off)
fp = session.construct_fixed_point(saddle_guesses(10, 1)["saddle"])
session.orient_eigenvectors(fp, {"unstable": np.array([-1, 0]), "stable": np.array([0, 1])})
session.initialize_both_manifolds(fp)
session.grow_n_times(fp, "unstable", num_iterations=8)   # fixed count: no notion of escape, only the point budget
session.grow_until_turnaround(fp, "stable")
session.compute_intersections([fp])          # registers anchors + crossings, infers iterates
session.trim_stable_manifolds(fp)
session.create_bridges(fp)                   # bridges keyed by BridgeId
session.classify_strong_pips()               # default pip, remembered across generations
A = session.arrangement()                    # faces -> Region objects
topo = session.topology()                    # one recompute: pseudoneighbors, holes, partition from the pip ...
topo.classes                                 # = session.bridge_classes(): the lettered alphabet
topo.minimal                                 # hole bridges + images of all but the zeroth-hole ones
topo.iterated                                # homotopy partition cut by the minimal trellis's image bridges
topo.dual_graph                              # StableNodes / FaceNodes over its sparse arrangement
topo.dynamics                                # itineraries, words, refined classes, transition graph
```

**Data model — how a manifold is stored.** One `PointStore` per workbench holds every point as a row (xy, cdist, image and preimage rows; NaN / -1 for none). The order along a curve is a `Chain` of the store: the rows of one physical curve in curve order, each row on at most one chain (the store's `_chain` / `_position` columns, O(1)); a curve (branch, bridge, partial piece, blast image curve) is a view over a chain that stores its root and tail as rows of its `store` (the root may be the periodic point's `BranchPoint`), found from the root's row on every read (`get_cdist_array` reads on to the chain's end, and the neighbours refinement and the resolution ratio read lie one point past the curve's ends); `ids` are its rows from root to tail. `BranchPoint` is the periodic point and never a row: a view of its `FixedPoint` (the orbit point's coordinates, cdist 0.0 on both manifolds, the neighbouring orbit points as its image and preimage) and the anchor of the chains on its slots, which the fixed point's slot table `(stability, orbit_index, branch) -> Chain` holds (`BranchPoint.chain` / `attach`). The iterate links are store columns. `root` / `tail` and a bridge's `head` are `End(id, x, y, cdist)` records, values with no links, or the `BranchPoint`. `BaseManifold`'s end setters bump `version`, and one `_collect` gather behind every getter returns a fresh array per call.

**Manifold key.** `ManifoldKey = (FixedPoint, Stability, orbit_index, branch_index)`. Every `BaseManifold` and `Bridge` carries its key (required at construction); `workbench.register_manifold(key, manifold)` asserts they agree. `FixedPoint.advance_key(key, n)` is the ONE rule for what n map steps do to a key (orbit index advances; the branch flips only when the orbit index wraps and the point has inversion). `FixedPoint.num_branches` is 2 iff inversion (`k_value == 2 * period`); `per_step_beta(stability)` is the per-map-step canonical-distance factor `|λ|^(1/period)` (a branch return is `k_value` steps and costs `λ^num_branches`); `branch_cycle(stability)` lists the `k_value` keys in forward-map order. `period` is always the MINIMAL period: `construct_fixed_point` raises `ValueError` on an orbit that repeats with a proper divisor of the requested period, and `k_value = 2 * period` is never a period to request.

**Invariants the code asserts (keep them):** cdist non-decreasing along a manifold; every registered crossing is unstable × stable; every bridge is an arc between consecutive crossings on one unstable branch, its `BridgeId` in unstable-cdist order (asserted at registration); holes of one origin share `bridge_side` (parity-flipped under an orientation-reversing map); a hole bridge whose crossings share a stable branch has alternating crossing signs (one row at both ends); exactly one partition element owns each crossing per side (by id at a boundary, by EXACT cdist elsewhere: boundaries are registry floats, asserted); the iterate table is a partial bijection; an image pair lies in at most one bridge's image chain (the map is a bijection); every itinerary has even length (`trellis_itinerary` asserts it). Held by construction rather than asserted: `image_of(region)` preserves area (an image whose area disagrees is rejected, None returned), and refined classes never change `BridgeClass` identity. Dedup is relative (`DEDUP_RTOL`); the topology reads no absolute cdist slack (anchors by identity, `is_anchor`; ownership and containment exact; scaled cdists carry their RELATIVE error, `SCALING_RTOL`, `collision_rtol`), and `cdist_tol` is only the absolute slack of degenerate bridge cuts and polyline clipping. A cross-side pair on one branch is flagged and logged, never asserted.

**Point budget (a resource guard, not an invariant).** `PointBudgetExceeded` is an exception type, never an `assert`, and never feeds `is_reliable` or the provisional flags. It is raised mid-step and the state is NOT resumable (a growth chain partly mapped and under-refined; a blasted bridge's points linked to a half-refined image while `iterated` stays False, so `iterate_bridge` refuses that bridge again): rebuild with fewer steps, a stop condition (`grow_until_bounded`), a coarser `area_cutoff` or a larger budget. The generation still advances. `blast_zone` never swallows it: it re-raises with the zone, step and bridge appended (`exc.blast_context`, a declared attribute, None outside a blast; `MaxIterationsReached` and `TURNAROUND_LOG_STRETCH` are exported). Its own `max_points` budget is the clean stop (between iterations, resumable).

**Generation counter.** `IntersectionRegistry.generation` bumps on every registry mutation; `TangleWorkbench.generation` is a monotone token over its own mutations, the registry generation and every manifold's `version`. A `Trellis` records `_built_generation`; `TangleSession.trellis()` / `arrangement()` rebuild when it differs, and `TangleSession.topology()` rebuilds when the generation or the selection's strong pips differ. There is no manual invalidation.

**Intersection detection.** `compute_intersections` bulk-loads all manifold segments into the two rtrees, one per stability (`Tangle.add_manifolds`; each unstable segment is queried against the stable index); `iterate_bridge` registers image bridges query-only (a bridge is unstable, so everything it can cross is stable and already indexed). A blast's image curves are computed manifold: the workbench keeps them (`_image_curves`) and every `compute_intersections` re-indexes them query-only (on a fresh index, a curve growth has merged into a branch adds no segment and is dropped; `reset=False` keeps every curve), and `create_bridges` cuts them (one crossed fewer than twice is a partial piece, the curve itself), so a recompute, a growth round or a zone (re)definition after a blast keeps every crossing, bridge, partial piece and `iterated` flag. Crossings are resolved once, registered in the registry, then bridges are cut at those exact crossings of N. The iterate table is EXACT (stage 2 above), so the topology only looks links up. How well crossings are resolved is set by the machine's `area_cutoff`: the library default is 1e-7, the cheapest cutoff the stress campaign found converged on every case, and a recipe tuned at 1e-4 passes it explicitly. No same-stability pair is ever formed (one rtree per stability). Registry ids survive `compute_intersections(preserve_ids=True)`, and they are REPRODUCIBLE: crossings are registered along each unstable branch in unstable-cdist order, never in the iteration order of a set of segment ids, and segment ids are drawn per index (`Tangle._next_sid`), so two builds of one case in one process number them alike and give byte-equal crossings. `compute_intersections` REPLACES `workbench.intersection_registry` (unless `reset=False`) and returns the new one: re-fetch the registry after every call, a held reference goes stale (logged at DEBUG). **Resolution.** Every detected crossing carries `resolution_ratio = min(l_u, l_s) * |sin| / max(h_u, h_s)` (chord deviations, floor `1e-8 * min(l)`; anchors/synthetics None). A detection below `resolution_ratio_threshold` (3), or in a run of detections closer than their chord deviation, is NOT a crossing of N: it is registered and reported, and no path reads it (stage 1 above). `report_resolution` logs ONE WARNING for new unresolved detections, ending with the remedy "refine", and one for new same-stability polyline crossings in the padded crossing box (INFO outside it), each finding once, on the `TangleWorkbench` logger; it runs at the end of top-level `compute_intersections(diagnose=True)` (growth loops pass False; `grow_until` reports once when its predicate holds) and once per `blast_zone(diagnose=True)` call, which only COUNTS the same-stability hits its new image bridges take part in and remembers none. The same-stability readings are `numerics/diagnostics.py`'s: `same_stability_crossings(workbench, fixed_points, region=, pad=)` (u×u / s×s polyline crossings incl. self-crossings, vectorised sweep; `SameStabilityCrossing` with `local_area`, `suggested_area_cutoff`, `in_tangle_region`), `count_same_stability_crossings(workbench, bridges)` (the hits involving some new curves, counted: only pairs holding a new segment are tested, no per-hit object; `SameStabilityCount`) and `ResolutionReport` (`same_stability_count` on a blast's report). The same-stability flag never feeds `is_reliable` or the provisional flags.

## Coding Style

- **Docstrings**: Google-style with `Args:`, `Returns:`, `Raises:`, and `Note:` sections. Write them for every public class, `__init__`, and method. One-sentence private helper docstrings are fine.
- **Dev Notes**: Module-level `"""Dev Notes: ..."""` blocks are the preferred place for longer-term design questions and open issues — not inline TODOs scattered through methods.
- **Type hints**: Always annotate function signatures. Use `Literal["unstable", "stable"]` for the stability parameter. Use `Optional[X]` and `NDArray[np.float64]` from `numpy.typing` for array return types.
- **imports**: `from __future__ import annotations` at the top of every file that uses forward references. Group: stdlib, then numpy/scipy, then local `.` imports.
- **Naming**: `PascalCase` for classes, `snake_case` for everything else. `_single_leading_underscore` for private methods.
- **Avoid bare print statements**: Use `logging` (the module already configures a `NullHandler` logger in `ManifoldMachine.py`). Debug output that ends up in production code is a recurring issue — prefer `logger.debug(...)`.
- **Comments**: Sparse inline comments only when the invariant is non-obvious. Do not leave blocks of commented-out old code in committed files — the dev notes pattern or git history is the right place for those.
- **Assertions**: Used to check invariants (e.g., cdist ordering after merge). Keep them; they are the primary correctness guard here.
