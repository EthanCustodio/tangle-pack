This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Project Is

`tanglepack` is a Python library for computing and visualizing **heteroclinic/homoclinic tangles** — the stable and unstable manifolds of saddle fixed points in 2D discrete dynamical systems (area-preserving maps). The core scientific workflow is: define a map → find a fixed point → initialize manifolds → grow them iteratively → detect intersections → extract bridges and resonance zones.

There is currently no GUI frontend: the old Dash dashboard (`tanglepack_webdash`) and PySide6 GUI (`tanglepack_gui`) were removed in July 2026 (recoverable from git history) and a new GUI will be built from scratch later. The library is used through scripts, notebooks, and the `TangleWorkbench`/`TangleSession` APIs.

## Fundamental Invariant — Which Manifolds Can Intersect

This is a hard physical law of the system, not a convention, and it must inform every piece of intersection/bridge logic:

- **Two unstable manifolds can never intersect each other.** Two stable manifolds can never intersect each other. This holds whether the manifolds belong to the same fixed point or to different fixed points.
- **Only an unstable manifold can cross a stable manifold** (homoclinic when they share a fixed point, heteroclinic when they belong to different fixed points).

Why: a point on a stable manifold converges to that manifold's fixed point under forward iteration; a point on an unstable manifold converges to its fixed point under backward iteration. A shared point of two stable manifolds would have to converge forward to *both* fixed points at once (and a shared point of two unstable manifolds would have to converge backward to both) — impossible. The same uniqueness argument forbids a manifold from crossing itself.

**Implication for the code:** a same-stability pair (u×u or s×s) appearing in `_intersecting_segments` is *always* a numerical artifact — two near-parallel polygonal approximations straddling near a tangency, not a real crossing. Such pairs should be filtered out (and are worth logging), but they must never be treated as a legitimate geometric case to model.

## Area Preservation

These maps are **area-preserving**: mapping any region forward (or backward) produces a region of exactly the same area. This is a fundamental property of the system, not an approximation.

A consequence used by the topological layer: for an intersection point, the product of its stable and unstable canonical distances behaves like a preserved area (one forward iterate scales the unstable cdist up by the per-step eigenvalue factor and the stable cdist down by the same factor, so the product is unchanged along an iterate chain). Note, however, that two *different* iterate chains generally have *different* such products — equal products do not imply two points are on the same chain, so do not use the product alone to decide chain membership. Compare the stable and unstable canonical distances individually (a collision on both means the same point) when you need to know whether two intersections are iterates.

## Bridge classes and the dual graph

The topology layer reads the combinatorics of a trellis's arrangement without growing anything further, in three steps:

- **Row (which side a bridge end is on).** The stable manifold is oriented anchorward. At a crossing with sign `s = crossing_sign(p)`, `row(first) = left iff s > 0` and `row(second) = left iff s < 0` — a bridge leaves its first endpoint along `u+` and enters its second along `u-`, and `u+` sits on the left of the dynamical stable direction exactly when `s > 0`. This combinatorial rule needs no geometry, agrees with the same-branch invariant above whenever the two signs differ, and works even at a synthetic anchor.
- **Bridge class.** A `BridgeClass` is the UNORDERED pair `{X, Y}` of `ElementRef`s the bridge's two rows resolve to — the homotopy class of arcs between those two elements — oriented anchor outward (`source` is the anchor-nearer element: smaller homotopy `element_id` FIRST, on one branch or across branches, then `element_sort_key` — `anchor_outward_key`, 2026-09-30; before that a class between two orbit branches was oriented by orbit index, which put spurious orbit-shift inverses in period-k words). A member bridge traversed in the unstable direction runs `source -> target` (direction `+1`, symbol `a`) or back (`-1`, symbol `a^-1`); both belong to the one class. A bridge with both ends in ONE element is a loop: it is the image of a bridge that did connect two elements and it will keep mapping into that element, so it is FOLDED into the class of its first non-loop ancestor along the registry preimage chain (`Trellis.iterate(-1)` + `bridge_between`, never the map). A loop with no registered ancestor stands alone as a `BridgeClass(x, x)` entry and is logged. **A class is INERT iff it maps to no active class** (author's definition, 2026-09-16): each non-loop member's forward image is the chain of consecutive registered crossings between the `+1` iterates of its endpoints (`_image_chain`, table lookups only) and each image pair is classed by the same row/element rule — a pair NO bridge object spans still has a class or is still a loop (the k=2.8 blasted tangle's exterior class is inert through such a virtual loop). Inert = at least one resolvable image and every resolvable image is a loop or in an inert class; a class mapping to an active class, ITSELF included (the anchor bridge maps over itself), is active; members with no registered image are no evidence either way (k=10's inert class has one); a folded loop member counts as loop evidence, so "holds a loop" still implies inert. Computed as a fixed point (`_resolve_inertness`), recorded on the entry (`inert`, `image_classes`, `image_loops`, `unresolved`). Inertness stays evidence-based: grow or blast until the images are registered. `bridge_classes(trellis, partitions)` returns a `BridgeClassTable` of `BridgeClassEntry`s (members with directions, image evidence, `letter`, `zone_key`, `min_unstable_cdist`) grouped by TANGLE (author, 2026-09-30: `entry.tangle` = the position in `trellis.fixed_points` of the one fixed point owning every member's unstable branch and both elements, None for a class connecting two tangles; tangle 0's classes, then tangle 1's, …, then the connecting ones — unstable cdists of different saddles are never interleaved) and within a group sorted by each class's SMALLEST member first-crossing unstable cdist (author's rule, 2026-09-21: the class holding a tangle's anchor bridge comes first in its group; ties by `class_sort_key`); the session letters ACTIVE classes from its persistent `BridgeAlphabet` in that order (a class seen before keeps its letter, a new one takes the next) and records each class's resonance zone via `classify_bridge`. Inert letters, legends and transition-graph slots follow the same table order. Refined symbols (`a_1, a_2, …`) subdivide a class in `SymbolicDynamics.py` (see "Symbolic dynamics" below) and never change the class.
- **Face side of an arc.** The arrangement traverses every bounded face CLOCKWISE (the face on the right of each half-edge). A stable `Arc` traversed `hi -> lo` (`reverse=True`) runs in the stable dynamical direction, so that traversal's face is on the arc's `right`; traversed `lo -> hi` the face is on the `left`.
- **Holes propagate BACKWARD only** (author's rule, 2026-09-16). `punch_holes` punches the reference pairs (found on the strong pip's fundamental segment) and, PROVISIONALLY, their forward iterates `+1 .. +(k_value-1)` — the trajectory's appearances on the other branches of a period-k orbit, which is how those branches get their fundamental-segment holes — then `propagate_reference_holes` maps every reference bridge backward. A recorded pair at forward iterate `>= k_value` gets NO hole even when the trellis has registered the image crossings and a bridge spans them (a blast does exactly that): its region is the image of a hole still attached to the stable manifold, and only the uncomputed image of the bridge beyond it could justify a boundary there. `extend_pseudoneighbor_trajectories` still records the forward pairs — they are real pseudoneighbor pairs — it is the punching that stops. The period-k `+1..+(k-1)` exemption is a choice the author wants to revisit (`_is_forward_beyond_fundamental` is the one place it lives).
- **Minimal trellis.** The dual graph is built over a REDUCED trellis (`MinimalTrellis.py`): every bridge with a hole attached (`Hole.bounding_ids`), plus, for each hole bridge whose bridge class is ACTIVE, the bridges tiling its first forward image (`image_chain`, iterate table only; a subdivided image contributes every consecutive pair; a pair with no `Bridge` object is skipped with a WARNING). Inert hole bridges are kept but not mapped. The stable manifold is kept whole; the surviving nodes are the kept bridges' endpoints, the anchors and each stable branch's outermost crossing. The reduced snapshot is a synthetic `Trellis` sharing the parent's registry, and its `Arrangement` is built in `sparse=True` mode: unstable arcs come from the bridge list (not consecutive crossings) and an absent unstable ray is an absent wall (the two sectors merge), not a slit.
- **Partition families.** `PartitionFamily.py` holds one partition per `(branch, side)` behind a base class: `HomotopyPartition` wraps the hole-cut partition (`partition_stable_manifold`, unchanged), `IteratedHomotopyPartition` refines it by the minimal trellis's IMAGE bridges under the EMPTY-STRETCH rule (author, 2026-09-23). The stable manifold has EMPTY stretches, everything else is the inclusive shape: a hole's stretch (an open interval of the homotopy partition) is empty, and so is the footprint of a hole's image lobe — a hole `H` bounded by one bridge iterates forward into a stretched and folded lobe `f(H)` that sits on the manifold along its BASE (the chain's `(x_0, x_m)`) and folds through it along one CHORD per pair of consecutive interior crossings (`(x_1, x_2), (x_3, x_4), ...`, the doorways to its folds on the other side); base and chords are read off the hole bridge's full image chain (`_image_chain`, lookup only; only the crossings on the BASE's stable branch are paired into chords — an excursion across another orbit branch or fixed point folds nothing there, and a chain ending on another branch marks nothing, 2026-09-30), only for holes with a stretch (the anchor's one-sided hole marks nothing). Empty stretches are empty on BOTH sides. An image bridge's crossing belongs, on the row the bridge cuts, to the element AWAY from the empty stretch it abuts (`open_anchorward` when the empty stretch is anchorward, `open_outward` when outward; an empty stretch whose far end lies on another stable branch is no flank and is skipped with a WARNING; abutting both pinches a singleton; abutting none is a WARNING and no cut, `"no empty stretch"`; `Cut.partner` = the far end of the empty stretch). Every crossing then lies in the element of the stable edge the walk crosses there, so a refined class's occurrence names exactly the elements its members land in. k=2.8 two blasts: the hole `(6,5)`'s lobe has base `(10,7)` and chord `(8,9)` (its fold is the reference hole on the left), so `R_1^1=[0,10] R_1^2=(10,7) R_1^3=[7,6]`, `R_5^1=[3,8] R_5^2=(8,9) R_5^3=[9,4]`; the anchor lobe's fold `(4,3)` abuts the hole `(1,3)` at `3`, so `L_1^1=[0,3) L_1^2=[3,8]`; k=10 right row `[ ] ( ) [ ] ( ) [ ] ( ) [ ]`, left `[ ) [ ] ( ) [ ]`. History: commit `2a2e35a` closed the element under every image bridge; the 2026-09-21 FOOTPRINT rule opened every lobe's base and chords, the anchor lobe's included (it put `3` in `L_1^1`, rejected); closing every bridge's stretch put `9` in `R_5^2` (rejected the same day). An existing hole boundary is never re-cut; the other side is untouched at an image endpoint (a crossing shared by two consecutive pieces is cut on both rows, once per piece). Iterated elements record `parent_element_id` (the homotopy element they refine) and `cut_by` (the innermost image bridge they lie under). `ElementRef` carries no family tag: never mix refs of the two families in one structure.
- **Fundamental segment.** The strong pip `q0` DECLARES the stretch where a walk may cross the stable manifold: on the pip's own stable branch, the edges meeting `(cdist(f^k(q0)), cdist(q0)]` with `k = k_value` (via `Trellis.image_cdist`), and nothing on any other branch (kept for period-k orbits too, author 2026-09-30: the other `k_value - 1` branches are walls everywhere). The same pip gathered twice (`trellis(fp)` and `trellis([fp])`) counts once; two different pips on one branch raise. There the two side nodes of a stable edge are UNIFIED into one solid, traversable `StableNode`; everywhere else each edge has two open side nodes that are walls. Choosing a different candidate pip moves the unified set without trimming; no pip unifies nothing and warns. `TangleSession.dual_graph` keys its cache on the gathered pips for that reason. Faces carry NO bridge class (the relation is not one to one); a walk alternates face -> stable node -> face and collects the stable elements it visits.
- **The row invariant.** `row_of_end` reproduces the same-row invariant exactly when the two crossing signs differ — with equal signs the rows come out opposite, which is what a bridge that crosses the stable branch would look like, so the invariant check `check_bridge_rows_consistent` is the geometric guard.
- **Symbolic dynamics** (author's algorithm and rules, 2026-09-21; `ElementNaming.py`, `DualWalk.py`, `SymbolicDynamics.py`; lookup only, the map is never called). The image of a bridge class is a WORD in the other classes, read off a walk of the dual graph.
  - *Names.* Homotopy elements are named side-tagged, anchor outward, 1-based, per stable branch: `L_1, L_2, …` / `R_1, R_2, …` (subscript = `element_id + 1`). Iterated children carry a superscript counting the parent's children anchor outward, `R_1^1, R_1^2`; an unsplit element prints plain (`R_3`). Since 2026-09-30 (author) EVERY name carries its branch's `orbit.branch` code in the subscript before the element index — text `R_(1.0;2)^1`, mathtext `$R_{1.0;2}^{1}$` (`short_text` is the old `R_2^1`; `lookup` accepts it when unambiguous) — and, when the homotopy family spans more than one fixed point, the fixed point's letter (`A:R_(1.0;2)^1`, mathtext left superscript `${}^{A}R_{1.0;2}^{1}$`). The letter is `FixedPoint.label` (the workbench stamps `A, B, …` in construction order), which also prefixes `ElementRef.label` (`A:p3@1.0/L#2`) so same-period saddles never collide. `ElementNaming.letters`, `letter_of`, `branch_code(key)` (`"1.0"` / `"A 1.0"`, the label of a stable arc or row). The fixture facts in this file are written in the short form (their branch is `0.0`). `ElementNaming(homotopy, iterated)` is the ONLY place that knows which family a ref belongs to (`ElementRef` carries no family tag): `homotopy_name` reads a homotopy ref, `name`/`parent_of` an iterated one, `children_of` lists a parent's iterated children, `ref_of`/`lookup` invert. `DualGraph.naming` names every `StableNode` per side (`names`, `label`).
  - *Landing* (`land_element`). Each homotopy element of a class maps one step into ONE iterated element `X'`: branch `advance_key(key, 1)`, side flipped iff the map is not `orientation_preserving`, ends via `Trellis.image_cdist` (table first), the anchor end to 0, an unbounded high end scaled by `per_step_beta("stable")`; the target is the owner of the span's midpoint (`interval_at`). A span straddling a cut is a WARNING with `contained=False` and `covering` filled — handled defensively, not modelled. Never cross-check against the owner of a member endpoint's `+1` iterate: an image endpoint on an existing hole boundary (never re-cut) can be owned by the neighbour, and a boundary point's owner says nothing about where the span lands.
  - *Singletons.* A singleton element `[x, x]` (a hole abutting the anchor, or two holes pinching a crossing) owns no stable edge and no dual-graph node. Singletons map to singletons and are NOT walked: the image is `Trellis.iterate(x, 1)` (under backward-only holes the image crossing is a singleton only when the holes pinching it are punched; a forward-iterate pinch, or the trimmed end at the pip, leaves the image a boundary point of a full element — `land_element` logs that at INFO and the trellis path is unaffected) and the class itinerary is read off the REGULAR trellis — the `_image_chain` of its first non-loop member with a registered chain, via `trellis_itinerary` (`source == "trellis"`, `search is None`). No registered chain → unresolved, "grow or blast". For a direction `-1` member the trellis itinerary is the element-wise REVERSE of the forward chain's itinerary: rows are read on the forward `BridgeId` order (swapping the pair would flip every row).
  - *The walk* (`shortest_walks`). From `X'` to `Y'` over the dual graph, the shortest simple walk face → unified node → face (walls never crossed, a merged face on both sides of a node is skipped), recording at every crossing BOTH sides: the entry-side element then the exit-side element. The itinerary therefore has EVEN length and splits into DISJOINT consecutive pairs; a bridge only connects same-side elements (possibly on different branches), so each pair, read through its homotopy parents (`oriented_class`), is one class or its inverse (k=10: `R_1^1 R_3^3 | L_3 L_1^2 | R_3^1 R_1^3`). Several shortest walks with different itineraries = `ambiguous`: all kept, WARNING, the first (deterministic order) feeds the rest, `is_reliable` is False. Registered member images (`registered_evidence`, same translation) are compared at WORD level (`verified`) — evidence only, the walk is the answer; a length mismatch is a WARNING (the shortest walk can be topologically wrong where nothing is registered). Exact-itinerary disagreement is INFO only, because a registered image endpoint can sit exactly on a closed boundary.
  - *Symbols.* An active class uses its session letter; inert classes take a SEPARATE series `u, v, w, x, y, z, uu, …` from `inert_letters` (skipping letters active classes already carry; the session `BridgeAlphabet` stays active-only); a pair whose class no bridge spans is VIRTUAL, named `new1, new2, …` with a WARNING. Directions are ALWAYS shown, inert included: k=10 reads `a -> a u^-1 a^-1` (the walk crosses `u = {L_1, L_3}` against its anchor-outward orientation). Pairs falling into one element are loops: dropped from the word, kept in `loops`. A cross-side pair is flagged (`cross_side`) and logged, never asserted.
  - *Refinement* (`refine`). Occurrences come ONLY from the walked/trellis itineraries of ALL classes, never from registered images. A class whose symbol occurs with two or more distinct iterated pairs splits into `a_1, a_2, …` anchor outward (`RefinedClass`); every refined child inherits the parent's word rewritten in refined symbols — k=10: `a_1 = (R_1^1, R_3^3)`, `a_2 = (R_1^3, R_3^1)`, `a_1 -> a_1 u^-1 a_2^-1` AND `a_2 -> a_1 u^-1 a_2^-1`. Members are matched to refined children by their OWN endpoint owners (`match_members`; the empty-stretch cut makes every image crossing belong to the element of the edge the walk crosses there, so the fixtures match every member); an unmatched member goes to `unmatched_members` at INFO (`plot_bridges_by_class` draws one in its parent letter's own palette slot, labelled "(unmatched)"). A refined class never changes `BridgeClass` identity.
  - *Transition graph / matrix* (`transition_graph`, `transition_matrix`; `refined=True` by default). Nodes are the refined ACTIVE symbols plus any virtual ones, one edge per token with `weight` = multiplicity; INERT classes are not in the graph or the matrix (author, 2026-09-23: they contribute nothing to the dynamics, their symbols stay visible in the words; a token naming one is skipped, an inert class with a non-empty word of its own warns); virtual symbols are sinks. k=10: nodes `a_1, a_2`, matrix `[[1,1],[1,1]]`. No spectral radius is computed or shown (author, 2026-09-23: removed until its meaning for the trellis is settled).
  - *Fixture facts* (letters by cdist since 2026-09-21). k=2.8 two blasts: `a = {R_1,R_5}` (the anchor class), `b = {R_3,R_5}`, `c = {R_1,R_3}`, `u = {L_1,L_3}`; `a -> a u^-1 b^-1`, `b -> c`, `c -> a u^-1 a^-1`; `a` refines into `a_1 = (R_1^1, R_5^3)`, `a_2 = (R_1^3, R_5^1)` and every member matches a child; matrix over `(a, b, c)` = `[[1,1,0],[0,0,1],[2,0,0]]`. k=2.8 one blast: the single active class is singleton-to-singleton, resolved via the trellis path, word `a u^-1 v^-1`; the inert classes are trivial loops. `TangleSession.symbolic_dynamics()` caches on `(generation, partition signature, strong pips)` like `dual_graph`.

## Core Library Architecture (`src/tanglepack/`)

Three subpackages plus examples. **Dependency rule: `numerics` and `topology` never import `loom`** (loom sits on top and weaves the other two together).

- `numerics/` — the numerical engine: maps, fixed points, manifold growth, crossing detection, bridges, the intersection registry.
- `topology/` — combinatorial structures over the registry: the `Trellis` snapshot, strong pips, pseudoneighbors, holes, the stable partition, the planar `Arrangement` of regions, bridge classes, the minimal trellis and dual graph, and the symbolic dynamics (element names, dual-graph walks, words).
- `loom/` — cross-layer algorithms that read topology and act on numerics: `TangleSession`, resonance zones, blasting.
- `examples/henon.py` — the one Hénon map definition (`henon_map(k, b)`, `henon_map_inverse`, `henon_jacobian`, `saddle_guesses`) used by tests and scripts (the notebooks still carry their own copies; see the plan's Deferred list); `examples/henon_cases.py` — the shared higher-period recipes `build_period3()` / `build_nested()` → `TangleBuild` (session, fixed points outermost first, pips, title, slug), used by the figure scripts and `tests/test_higher_period_cartoon.py`. Period 3 at 13 unstable steps is CLOSED (`a -> b -> c -> a u^-1 w^-1`, no image bridges; blasting changes nothing); the `check_holes_share_bridge_side` trip at 15–16 steps and 6+ blasts is fixed (2026-10-02: a propagated hole's side is read on its image sub-arc, a direct hole's from its crossing signs), but those runs are unreliable (an unreachable class, a virtual `new1`; open). Nested needs two outer blasts for every class to resolve.

**Symbolic-itinerary figures.** `scripts/symbolic_figures.py` `draw_panels` writes six panels per case into `figures/henon_symbolic_itineraries/<slug>/` — `trellis`, `partitions`, `cartoon`, `itineraries`, `transitions`, `transitions_refined` — each as `.png`, `.svg` and `.fig.pickle` (networkx's curved edge labels are frozen into plain `Text` before pickling). The cartoon panel is `shape="circle"`. The trellis panel draws ONLY the minimal trellis's bridges (`plot_bridges_by_class(..., bridge_ids=minimal.kept_bridge_ids)`): every blast child is a class member, so an unfiltered plot grows with each blast even though the minimal trellis does not (nested: 16 kept bridges from 2 to 5 outer blasts while the trellis goes 38 -> 72).

The entry point for programmatic use is `TangleSession` (a facade over one `TangleWorkbench`, caching one `Trellis` per fixed-point selection and delegating unknown attributes to the workbench):

```python
import numpy as np, tanglepack
from tanglepack.examples.henon import henon_map, henon_map_inverse, henon_jacobian, saddle_guesses

session = tanglepack.TangleSession(henon_map(10), henon_map_inverse(10), henon_jacobian(10))
fp = session.construct_fixed_point(saddle_guesses(10, 1)["saddle"])
session.orient_eigenvectors(fp, {"unstable": np.array([-1, 0]), "stable": np.array([0, 1])})
session.initialize_both_manifolds(fp)
session.grow_n_times(fp, "unstable", num_iterations=8)
session.grow_until_turnaround(fp, "stable")
session.compute_intersections([fp])          # registers anchors + crossings, infers iterates
session.trim_stable_manifolds(fp)
session.create_bridges(fp)                   # bridges keyed by BridgeId
T = session.trellis(fp)                      # cached by generation
T.classify_strong_pips(); T.compute_pseudoneighbors(); T.punch_holes(); T.partition_stable_manifold()
A = session.arrangement()                    # faces -> Region objects
M = session.minimal_trellis()                # hole bridges + images of the active ones
P = session.iterated_partition()             # homotopy partition cut by M's image bridges
G = session.dual_graph()                     # StableNodes / FaceNodes over M's sparse arrangement
S = session.symbolic_dynamics()              # itineraries, words, refined classes, transition graph
```

**Data model — how a manifold is stored.** Points form two simultaneous doubly-linked lists inside `Point`: the *geometric* list (`forward`/`backward`, order along the curve) and the *iterate* list (`next_iterate`/`prev_iterate`, which point maps to which). `BranchPoint` is the root anchored at the periodic point. `BaseManifold` holds `root`/`tail` (setters bump `version`) and one `_collect` walker behind every getter; bridges memoise their point arrays (read-only).

**Manifold key.** `ManifoldKey = (FixedPoint, Stability, orbit_index, branch_index)`. Every `BaseManifold` and `Bridge` carries its key (required at construction); `workbench.register_manifold(key, manifold)` asserts they agree. `FixedPoint.advance_key(key, n)` is the ONE rule for what n map steps do to a key (orbit index advances; the branch flips only when the orbit index wraps and the point has inversion). `FixedPoint.num_branches` is 2 iff inversion (`k_value == 2 * period`); `per_step_beta(stability)` is the per-map-step canonical-distance factor `|λ|^(1/period)` (a branch return is `k_value` steps and costs `λ^num_branches`); `branch_cycle(stability)` lists the `k_value` keys in forward-map order.

**Invariants the code asserts (keep them):** cdist non-decreasing along a manifold; every registered crossing is unstable × stable; every bridge is an arc between consecutive crossings on one unstable branch; holes of one origin share `bridge_side` (parity-flipped under an orientation-reversing map); a bridge whose crossings share a stable branch has the same row at both ends; exactly one partition element owns each crossing per side; `image_of(region)` preserves area; every itinerary has even length and splits into disjoint same-side pairs (`trellis_itinerary` asserts the length; a cross-side pair is flagged and logged, not asserted); refined classes never change `BridgeClass` identity.

**Generation counter.** `IntersectionRegistry.generation` bumps on every registry mutation; `TangleWorkbench.generation` is a monotone token over its own mutations, the registry generation and every manifold's `version`. A `Trellis` records `_built_generation`; `TangleSession.trellis()` / `arrangement()` rebuild when it differs. There is no manual invalidation (`invalidate_trellises()` is a deprecated no-op).

**Intersection detection.** `compute_intersections` bulk-loads all manifold segments into the rtree (`Tangle.add_manifolds`); `iterate_bridge` registers image bridges query-only (a bridge is unstable, so everything it can cross is stable and already indexed). Crossings are resolved once, registered in the registry, then bridges are cut at those exact crossings. Same-stability pairs are discarded as numerical artifacts; near-parallel pairs are logged and discarded. Registry ids survive `compute_intersections(preserve_ids=True)`.

## Coding Style

- **Docstrings**: Google-style with `Args:`, `Returns:`, `Raises:`, and `Note:` sections. Write them for every public class, `__init__`, and method. One-sentence private helper docstrings are fine.
- **Dev Notes**: Module-level `"""Dev Notes: ..."""` blocks are the preferred place for longer-term design questions and open issues — not inline TODOs scattered through methods.
- **Type hints**: Always annotate function signatures. Use `Literal["unstable", "stable"]` for the stability parameter. Use `Optional[X]` and `NDArray[np.float64]` from `numpy.typing` for array return types.
- **imports**: `from __future__ import annotations` at the top of every file that uses forward references. Group: stdlib, then numpy/scipy, then local `.` imports.
- **Naming**: `PascalCase` for classes, `snake_case` for everything else. `_single_leading_underscore` for private methods.
- **Avoid bare print statements**: Use `logging` (the module already configures a `NullHandler` logger in `ManifoldMachine.py`). Debug output that ends up in production code is a recurring issue — prefer `logger.debug(...)`.
- **Comments**: Sparse inline comments only when the invariant is non-obvious. Do not leave blocks of commented-out old code in committed files — the dev notes pattern or git history is the right place for those.
- **Assertions**: Used to check invariants (e.g., cdist ordering after merge). Keep them; they are the primary correctness guard here.
