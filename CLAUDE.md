# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Project Is

`tanglepack` is a Python library for computing and visualizing **heteroclinic/homoclinic tangles** — the stable and unstable manifolds of saddle fixed points in 2D discrete dynamical systems (area-preserving maps). The core scientific workflow is: define a map → find a fixed point → initialize manifolds → grow them iteratively → detect intersections → extract bridges and resonance zones.

There is currently no GUI frontend: the old Dash dashboard (`tanglepack_webdash`) and PySide6 GUI (`tanglepack_gui`) were removed in July 2026 (recoverable from git history) and a new GUI will be built from scratch later. The library is used through scripts, notebooks, and the `TangleWorkbench`/`TangleSession` APIs.

## Fundamental Invariant — Which Manifolds Can Intersect

This is a hard physical law of the system, not a convention, and it must inform every piece of intersection/bridge logic:

- **Two unstable manifolds can never intersect each other.** Two stable manifolds can never intersect each other. This holds whether the manifolds belong to the same fixed point or to different fixed points.
- **Only an unstable manifold can cross a stable manifold** (homoclinic when they share a fixed point, heteroclinic when they belong to different fixed points).

Why: a point on a stable manifold converges to that manifold's fixed point under forward iteration; a point on an unstable manifold converges to its fixed point under backward iteration. A shared point of two stable manifolds would have to converge forward to *both* fixed points at once (and a shared point of two unstable manifolds would have to converge backward to both) — impossible. The same uniqueness argument forbids a manifold from crossing itself.

**Implication for the code:** a same-stability pair (u×u or s×s) is *always* a numerical artifact — two near-parallel polygonal approximations straddling near a tangency, not a real crossing — and must never be treated as a legitimate geometric case to model. Since WP10 the `Tangle` never forms one: it keeps one rtree per stability and queries a segment only against the OTHER stability's index, so `_intersecting_segments` holds u×s pairs only (asserted). The same holds for a polyline crossing ITSELF (a Z-kink of one manifold) or a blast's image bridge crossing another same-stability curve: the Tangle index never tested those, and since 2026-10-07 `numerics/diagnostics.py` reports them as polygon ARTIFACTS of under-resolution (WARNING in the tangle box, INFO outside) -- a flag to refine, never a crossing.

## Area Preservation

These maps are **area-preserving**: mapping any region forward (or backward) produces a region of exactly the same area. This is a fundamental property of the system, not an approximation.

A consequence used by the topological layer: for a HOMOCLINIC intersection point, the product of its stable and unstable canonical distances behaves like a preserved area (one forward iterate scales the unstable cdist up by the per-step eigenvalue factor and the stable cdist down by the same factor, so the product is unchanged along an iterate chain). On a heteroclinic link `W^u(A) x W^s(B)` each side scales by its OWN saddle (the unstable cdist by `beta_A`, the stable by `1/beta_B`), so the product scales by `beta_A / beta_B` per step (NUM-20, WP10b: the iterate inference always did this; two laws had read A's factor for both sides). Note, however, that two *different* iterate chains generally have *different* such products — equal products do not imply two points are on the same chain, so do not use the product alone to decide chain membership. Compare the stable and unstable canonical distances individually (a collision on both means the same point) when you need to know whether two intersections are iterates.

## Bridge classes and the dual graph

The topology layer reads the combinatorics of a trellis's arrangement without growing anything further, in three steps:

- **Row (which side a bridge end is on).** The stable manifold is oriented anchorward. At a crossing with sign `s = crossing_sign(p)`, `row(first) = left iff s > 0` and `row(second) = left iff s < 0` — a bridge leaves its first endpoint along `u+` and enters its second along `u-`, and `u+` sits on the left of the dynamical stable direction exactly when `s > 0`. This combinatorial rule needs no geometry, agrees with the same-branch invariant above whenever the two signs differ, and works even at a synthetic anchor. An anchor is ONE point on every branch of its periodic point (D4: two stable and two unstable branches under inversion); a bridge of `u(o,b)` leaving it meets `s(o,b)` there (C7, `Trellis.stable_key_at`), whose sign is the anchor's own, so the rule reads the anchor end unchanged.
- **Bridge class.** A `BridgeClass` is the UNORDERED pair `{X, Y}` of `ElementRef`s the bridge's two rows resolve to — the homotopy class of arcs between those two elements — oriented anchor outward (`source` is the anchor-nearer element: smaller homotopy `element_id` FIRST, on one branch or across branches, then `element_sort_key` — `anchor_outward_key`, 2026-09-30; before that a class between two orbit branches was oriented by orbit index, which put spurious orbit-shift inverses in period-k words). A member bridge traversed in the unstable direction runs `source -> target` (direction `+1`, symbol `a`) or back (`-1`, symbol `a^-1`); both belong to the one class. A bridge with both ends in ONE element is a loop: it is the image of a bridge that did connect two elements and it will keep mapping into that element, so it is FOLDED FORWARD into the class of the first non-loop bridge up its image-chain parents (the one bridge whose `_image_chain` holds it; lookup only, never the map; one parent per pair, asserted: images of disjoint arcs are disjoint) (D2, 2026-10-07; the old backward walk over `iterate(-1)` broke at every fold-born crossing, BCG-2). A true orphan (no image chain reaches it) is logged once and left unclassed (`BridgeClassTable.orphans`), never lettered. **A class is INERT iff it maps to no active class** (author's definition, 2026-09-16): each non-loop member's forward image is the chain of consecutive registered crossings between the `+1` iterates of its endpoints (`_image_chain`, table lookups only) and each image pair is classed by the same row/element rule — a pair NO bridge object spans still has a class or is still a loop (the k=2.8 blasted tangle's exterior class is inert through such a virtual loop). Inert = at least one resolvable image and every resolvable image is a loop or in an inert class; a class mapping to an active class, ITSELF included (the anchor bridge maps over itself), is active; members with no registered image are no evidence either way (k=10's inert class has one); a folded loop member counts as loop evidence, so "holds a loop" still implies inert. Computed as a fixed point (`_resolve_inertness`), recorded on the entry (`inert`, `image_classes`, `image_loops`, `unresolved`). Inertness stays evidence-based: grow or blast until the images are registered. `bridge_classes(trellis, partitions)` returns the EVIDENCE table — every bridge's class — a `BridgeClassTable` of `BridgeClassEntry`s (members with directions, image evidence, `letter`, `zone_key`, `min_unstable_cdist`) grouped by TANGLE (author, 2026-09-30: `entry.tangle` = the position in `trellis.fixed_points` of the one fixed point owning every member's unstable branch and both elements, None for a class connecting two tangles; tangle 0's classes, then tangle 1's, …, then the connecting ones — unstable cdists of different saddles are never interleaved; the recipes construct the OUTERMOST fixed point first, so tangle 0 is it and its letter `A`, NEST-6, WP9) and within a group sorted by each class's SMALLEST member first-crossing unstable cdist (author's rule, 2026-09-21: the class holding a tangle's anchor bridge comes first in its group; ties by `class_sort_key`); the session letters the ALPHABET, `MinimalTrellis.alphabet` = the evidence entries with a member the minimal trellis keeps (D2, WP6; blast children are image evidence only, members kept whole), its ACTIVE classes from its persistent `BridgeAlphabet` in that order, keyed by the class's IDENTITY — the bounding crossings `(branch, side, lo_id, hi_id)` of its two elements (`PartitionInterval.identity`, `Topology.identity`; C2, WP8) — so a class keeps its letter across recomputes while its elements keep their bounds and a new one takes the next (element NAMES stay positional), and records each class's resonance zone via `classify_bridge`; `session.bridge_classes()` IS that alphabet. Inert letters, legends and transition-graph slots follow the same table order. Refined symbols (`a_1, a_2, …`) subdivide a class in `SymbolicDynamics.py` (see "Symbolic dynamics" below) and never change the class.
- **Face side of an arc.** The arrangement traverses every bounded face CLOCKWISE (the face on the right of each half-edge). A stable `Arc` traversed `hi -> lo` (`reverse=True`) runs in the stable dynamical direction, so that traversal's face is on the arc's `right`; traversed `lo -> hi` the face is on the `left`.
- **Holes propagate BACKWARD only** (author's rule, 2026-09-16). `punch_holes` punches the reference pairs (found on the strong pip's fundamental segment) and their forward iterates `+1 .. +(k_value-1)` (D5, 2026-10-07: kept) — the trajectory's appearances on the other branches of a period-k orbit, which is how those branches get their fundamental-segment holes — then `propagate_reference_holes` maps every reference bridge backward. A recorded pair at forward iterate `>= k_value` gets NO hole even when the trellis has registered the image crossings and a bridge spans them (a blast does exactly that): its region is the image of a hole still attached to the stable manifold, and only the uncomputed image of the bridge beyond it could justify a boundary there. `extend_pseudoneighbor_trajectories` still records the forward pairs — they are real pseudoneighbor pairs — it is the punching that stops. A `+j` appearance whose image crossings are not computed (the reference sits on the outermost lap of the longest unstable branch: a period-k chain is grown one map step at a time, so each branch reaches β further than the one before it) gets no hole and is named, per stable branch, in a `Pseudoneighbor` WARNING with its `image_cdist` prediction (WP5, PK-3); nothing is invented. A strong pip's unregistered orbit points are placed by `image_cdist`, so every branch is cut (PK-6). A hole's `bridge_side` (its side of its OWN bridge, never of the stable manifold): a direct hole reads it off its crossing signs; a propagated hole CARRIES it from the hole it propagates from, flipped every step only under an orientation-reversing map (author, 2026-10-07, `side_source = "signs" | "carried"`). The signs then decide the openings (D6, WP4 2026-10-08): at each non-anchor bound the hole opens the `outward` half iff `(crossing_sign > 0) == (bridge_side == "left")`, on `row_of_end` there. The reference hole carried back by the real inverse map and read at the nearest segment of the image sub-arc is kept as `measured_side`, a resolution FLAG only: a disagreement is one WARNING per `Trellis.punch_holes(diagnose=True)` (`geometry_flags`), never an assertion (NUM-2); the law `check_backward_holes_keep_bridge_side` re-measures independently. A HETEROCLINIC window pair (D7, WP9: two consecutive crossings of `W^u(A)` on B's stable branch, inside B's window) is a pair of B's tangle, judged against the crossings whose unstable side is A's with A's branch cycle and β (the arc is A's); its hole opens on B's branch and its backward chain runs along A's unstable cycle into A's bridges, holing A's partition too. It exists only on a trellis holding both tangles, so stages 4-6 run on the SELECTION's trellis. The backward chain moves the start bridge's two crossing ids by `Trellis.image_cdist` and finds the container by a bisect over the branch's crossing order; a hole sits on the WHOLE containing bridge by design (INT-2: the image sub-arc's far end lies beyond the trimmed stable manifold, so the trellis has no node to cut it at).
- **Minimal trellis.** The dual graph is built over a REDUCED trellis (`MinimalTrellis.py`): every bridge with a hole attached (`Hole.bounding_ids`), plus, for each hole bridge whose bridge class is ACTIVE (read from the EVIDENCE table, never the alphabet, which this trellis defines: evidence -> minimal trellis -> alphabet; kept as `MinimalTrellis.classes`, its restriction to the kept bridges is `MinimalTrellis.alphabet`), the bridges tiling its first forward image (`image_chain`, iterate table only; a subdivided image contributes every consecutive pair; a pair with no `Bridge` object is manifold that was never computed -- the image of a bridge no blast iterated, INT-9 / D9 -- and is skipped with a WARNING). Inert hole bridges are kept but not mapped. The stable manifold is kept whole; the surviving nodes are the kept bridges' endpoints, the anchors and each stable branch's outermost crossing. The reduced snapshot is a synthetic `Trellis` sharing the parent's registry, and its `Arrangement` is built in `sparse=True` mode: unstable arcs come from the bridge list (not consecutive crossings) and an absent unstable ray is an absent wall (the two sectors merge), not a slit.
- **Partition families.** `PartitionFamily.py` holds one partition per `(branch, side)` behind a base class: `HomotopyPartition` wraps the hole-cut partition (`partition_stable_manifold`, unchanged), `IteratedHomotopyPartition` refines it by the minimal trellis's IMAGE bridges under the EMPTY-STRETCH rule (author, 2026-09-23). The stable manifold has EMPTY stretches, everything else is the inclusive shape: a hole's stretch (an open interval of the homotopy partition) is empty, and so is the footprint of a hole's image lobe — a hole `H` bounded by one bridge iterates forward into a stretched and folded lobe `f(H)` that sits on the manifold along its BASE (the chain's `(x_0, x_m)`) and folds through it along one CHORD per pair of consecutive interior crossings (`(x_1, x_2), (x_3, x_4), ...`, the doorways to its folds on the other side); base and chords are read off the hole bridge's full image chain (`_image_chain`, lookup only; only the crossings on the BASE's stable branch are paired into chords — an excursion across another orbit branch or fixed point folds nothing there, and a chain ending on another branch marks nothing, 2026-09-30), only for holes with a stretch (the anchor's one-sided hole marks nothing). Empty stretches are empty on BOTH sides. An image bridge's crossing belongs, on the row the bridge cuts, to the element AWAY from the empty stretch it abuts (`open_anchorward` when the empty stretch is anchorward, `open_outward` when outward; an empty stretch whose far end lies on another stable branch is no flank and is skipped with a WARNING; abutting both pinches a singleton; abutting none is a WARNING and no cut, `"no empty stretch"`; `Cut.partner` = the far end of the empty stretch). Every crossing then lies in the element of the stable edge the walk crosses there, so a refined class's occurrence names exactly the elements its members land in. k=2.8 two blasts (ids as numbered since WP8): the hole `(6,7)`'s lobe has base `(8,11)` and chord `(9,10)` (its fold is the reference hole on the left), so `R_1^1=[0,11] R_1^2=(11,8) R_1^3=[8,7]`, `R_5^1=[4,9] R_5^2=(9,10) R_5^3=[10,3]`; the anchor lobe's fold `(3,4)` abuts the hole `(4,5)` at `4`, so `L_1^1=[0,4) L_1^2=[4,9]`; k=10 right row `[ ] ( ) [ ] ( ) [ ] ( ) [ ]`, left `[ ) [ ] ( ) [ ]`. History: commit `2a2e35a` closed the element under every image bridge; the 2026-09-21 FOOTPRINT rule opened every lobe's base and chords, the anchor lobe's included (it put the fold's crossing in `L_1^1`, rejected); closing every bridge's stretch put the chord's end in `R_5^2` (rejected the same day). An existing hole boundary is never re-cut; the other side is untouched at an image endpoint (a crossing shared by two consecutive pieces is cut on both rows, once per piece). Iterated elements record `parent_element_id` (the homotopy element they refine, found by EXACT containment, a singleton by its crossing's id — never by tolerant midpoint ownership, 2026-10-07) and `cut_by` (the innermost image bridge they lie under). `ElementRef` carries no family tag: never mix refs of the two families in one structure.
- **Trellis of the pip** (D10, D12, author 2026-10-08, WP8b). Choosing a strong pip `q0` CUTS the trellis to `T(q0) = (W^u[P, f^m(q0)], W^s[P, q0])`, both ends on the pip's orbit (`Trellis.cut_at_pip_orbit`; the `strong_pip` setter cuts, `None` restores the computed trellis): stable branch `j` ends at `c_s(f^j q0)`, `j < k_value`, and the unstable branch of `f^i(q0)` at `c_u(f^i q0)` for the `k_value` deepest registered `i` (`m` = the last forward iterate of `q0` the table holds; a missing orbit point is PLACED by `image_cdist` and flagged in one WARNING, PK-6). `f^-1` maps its unstable half into itself and `f` its stable half, so it is a genuine trellis, and a lambda-lemma copy deeper than the pip's own orbit is no crossing of it (BCG-5: the class count no longer drops under blasting; discovery stops at the depth the pip's orbit is registered to). It is stage 3's output and the ONE place N is decided: pseudoneighbors, holes, partition, classes, minimal trellis, dual graph and words all read the cut branches and bridges. A crossing past a cut is a point of X, not of N: it leaves every branch, and the unstable arc across it joins its two bridges into one (`Bridge.joined`, a bridge of the trellis the workbench never holds; resolve bridges through `trellis.bridge_between`, never `workbench.bridge`). `iterate` / `image_cdist` stay RAW registry lookups (X holds points outside T); a consumer that needs an iterate AS A CROSSING asks `image in trellis` (`Trellis.__contains__`). A per-fixed-point trellis is cut when its pip is set or restored; `TangleSession.trellis` cuts a selection of several fixed points at their pips on every read (a no-op while they are unchanged), so what `trellis()`, `arrangement()` and every plot show never depends on whether a product ran first (D1). That every crossing of a cut trellis lies inside its pip-orbit cuts holds by construction in `cut_at_pip_orbit` and is checked by the law `trellis_is_cut_at_the_pip_orbit`, not by an assertion. Classification un-chooses first, so candidates are always classified over the whole computed trellis. Several fixed points (WP9): a trellis holds a crossing only when BOTH its branches are selected, so a tangle's own trellis holds no heteroclinic crossing (its arcs are joined across them like across a cut) and the selection's holds them; cut at every pip it is `T(q0_A) ∪ T(q0_B)` (each branch at its own pip orbit; a heteroclinic crossing is in N iff inside A's unstable cut AND B's stable cut), `Trellis.pips` records the pip per fixed point.
- **Fundamental segment.** The strong pip `q0` DECLARES the stretch where a walk may cross the stable manifold: on the pip's own stable branch, the edges meeting `(cdist(f^k(q0)), cdist(q0)]` with `k = k_value` (via `Trellis.image_cdist`), and nothing on any other branch (kept for period-k orbits too, author 2026-09-30: the other `k_value - 1` branches are walls everywhere). Two different pips on one branch raise. There the two side nodes of a stable edge are UNIFIED into one solid, traversable `StableNode`; everywhere else each edge has two open side nodes that are walls. Choosing a pip cuts the trellis at its orbit (the bullet above), so the window is exactly `S \ f(S)`, where an image can cross the stable manifold away from the images of its ends, and the other `k_value - 1` branches are walls as a consequence (D10); no pip unifies nothing and warns. The session's `Topology` is keyed on the selection's pips for that reason. Faces carry NO bridge class (the relation is not one to one); a walk alternates face -> stable node -> face and collects the stable elements it visits.
- **The row invariant.** Rows are the signs' (`row_of_end`, D6): a bridge whose two crossings share a stable branch has one row at both ends exactly when the two crossing signs differ, so `check_bridge_rows_consistent` asserts the SIGN form (equal signs on one stable branch = the arc would cross that branch). The polyline's reading (`bridge_row_diagnosis`, `RowDiagnosis.geometry_disagrees`) is a resolution flag, never an assertion while the signs alternate: on a 2-4 node bridge the "approach" is the vector to the far node (NUM-1, WP4).

  - *Names.* Homotopy elements are named side-tagged, anchor outward, 1-based, per stable branch: `L_1, L_2, …` / `R_1, R_2, …` (subscript = `element_id + 1`). Iterated children carry a superscript counting the parent's children anchor outward, `R_1^1, R_1^2`; an unsplit element prints plain (`R_3`). Since 2026-09-30 (author) EVERY name carries its branch's `orbit.branch` code in the subscript before the element index — text `R_(1.0;2)^1`, mathtext `$R_{1.0;2}^{1}$` (`short_text` is the old `R_2^1`; `lookup` accepts it when unambiguous) — and, when the homotopy family spans more than one fixed point, the fixed point's letter (`A:R_(1.0;2)^1`, mathtext left superscript `${}^{A}R_{1.0;2}^{1}$`). The letter is `FixedPoint.label` (the workbench stamps `A, B, …` in construction order), which also prefixes `ElementRef.label` (`A:p3@1.0/L#2`) so same-period saddles never collide. `ElementNaming.letters`, `letter_of`, `branch_code(key)` (`"1.0"` / `"A 1.0"`, the label of a stable arc or row).   - *Landing* (`land_element`). Each homotopy element of a class maps one step into ONE iterated element `X'`: branch `advance_key(key, 1)`, side `side_after(side, 1, orientation_preserving)` (the one orientation rule, C3, WP11), ends via `Trellis.image_cdist` (table first), the anchor end to 0, an unbounded high end scaled by `per_step_beta("stable")`; the target is the owner of the span's midpoint (`interval_at`). A span straddling a cut is a WARNING with `contained=False` and `covering` filled: the walk still exists from the midpoint owner (D3), but under a correct partition the image lies in ONE element, so a straddle counts against `is_reliable` (INT-8, WP7). Never cross-check against the owner of a member endpoint's `+1` iterate: an image endpoint on an existing hole boundary (never re-cut) can be owned by the neighbour, and a boundary point's owner says nothing about where the span lands. The walk leaves from and arrives at the stable nodes the landing SPAN meets (overlap beyond the span's end error: none at a table end, `SCALING_RTOL` relative at a scaled one), not every node of `X'`: the hole bridges bounding `X` map onto the kept image bridges at the ends of `f(X)`, which `f(b)` cannot cross (D13, C14, WP9b; a span meeting no node falls back to all of them with a WARNING).
  - *Singletons.* A singleton element `[x, x]` (a hole abutting the anchor, or two holes pinching a crossing) owns no stable edge and no dual-graph node. Singletons map to singletons and are NOT walked: the image is `Trellis.iterate(x, 1)` (under backward-only holes the image crossing is a singleton only when the holes pinching it are punched; a forward-iterate pinch, or the trimmed end at the pip, leaves the image a boundary point of a full element — `land_element` logs that at INFO and the trellis path is unaffected) and the class itinerary is read off the REGULAR trellis — the `_image_chain` of its first non-loop member with a registered chain, via `trellis_itinerary` (`source == "trellis"`, `search is None`). No registered chain → unresolved, "grow or blast". For a direction `-1` member the trellis itinerary is the element-wise REVERSE of the forward chain's itinerary: rows are read on the forward `BridgeId` order (swapping the pair would flip every row).
  - *The walk* (`shortest_walks`). From `X'` to `Y'` over the dual graph, the shortest simple walk face → unified node → face (walls never crossed, a merged face on both sides of a node is skipped), recording at every crossing BOTH sides: the entry-side element then the exit-side element. The itinerary therefore has EVEN length and splits into DISJOINT consecutive pairs; on ONE branch a bridge only connects same-side elements (across two branches there is no side relation: the left of an inversion point's 0.0 is the right of 0.1, D4), so each pair, read through its homotopy parents (`oriented_class`), is one class or its inverse (k=10: `R_1^1 R_3^3 | L_3 L_1^2 | R_3^1 R_1^3`). **The non-crossing rule** (D13, author 2026-10-09; WP9b, `lobe_image_markers`, `holds_markers`): `f` is a homeomorphism and `W^u` never crosses `W^u`, so a member bridge `b` and the stable segment `sigma_b` between its ends bound a disk whose image `f(b) + f(sigma_b)` holds the image of every MARKER the lobe holds and of no other. Markers (`DualGraph.markers`): each periodic point at its anchor vertex (`f`: next orbit point) and each hole BESIDE ITS OWN BRIDGE on its `bridge_side` (`f`: hole `(origin, n)` -> `(origin, n + 1)`; a reference hole's image beside the kept image chain of its bridge; never the trellis lobe's corner, since a propagated hole lies beside its container's image sub-arc, INT-2). For every class with a MEMBER LOBE (a kept non-loop member with both ends on one stable branch, C13: not only ties -- the heteroclinic `bh`'s unique shortest walk broke it) the word is the shortest walk whose curve, closed by `sigma'` along the stable manifold (`DualGraph.enclosed`: a flood of the faces the curve cuts; any routing past a face's other boundary components), holds exactly those images; detours up to `MAX_DETOUR = 4` crossings, faces may repeat; a walk crossing `sigma'` or with crossing chords is rejected, one the midpoint model cannot draw (an edge crossed twice) is kept but never preferred by order; none found = `"no_admissible_walk"`, unresolved. The `max_walks` budget counts judgements there (the other walks of an itinerary already holding the markers are counted, not judged); running out before any judged walk holds them is status `"truncated"` with no walk, unresolved too (never `"no_admissible_walk"`, which would claim every walk up to the cap broke the rule). **Walls** (D13's own words, "f(bridge) cannot cross the images of the unstable arcs"; D14 "every bridge is the same"; WP9c, C17): every class's arcs lie on known unstable branches -- its members' (`Trellis.unstable_key_of`), or, for a class no computed bridge spans yet (D11), one map step past those of the class that named it (`advance_key`); arcs on different unstable branches are disjoint and so are their images, so the DECIDED walk (`unique` / `trivial`) of a class walked EARLIER on disjoint branches is a wall, and a tie loses every walk with a chord crossing one (`walk_chords`, `DualGraph.chords_cross`: the four ends of two chords on one face ring at four distinct positions, alternating; a shared end edge is free; `shortest_walks(walls=)`, counted in `WalkSearch.rejected`). A class with no member lobe (member-less, joining two stable branches, or connecting two tangles) is no special case: the walls decide its tie (the heteroclinic `bn`, a piece of `f^2` of the computed connecting bridge `(91, 92)`); a member-less class's `tangle` follows the table's rule with its arcs' branches for the members'. A tie no rule decides stays `ambiguous`: all kept, WARNING, the first (deterministic order) feeds the rest, `is_reliable` is False (none left on any law case, deep run or series step). Registered member images (`registered_evidence`, same translation) are compared at WORD level (`verified`) — evidence only, the walk is the answer (D3); a disagreement carries an `EvidenceDiagnosis` on the `ImageEvidence` (`position`, the `walked` and `registered` occurrences there, `cause` `"stable end"` when two consecutive crossings of the registered chain on ONE stable branch share a sign — the image passed the end of the computed stable branch, its crossings beyond the trim are unregistered — else `"walk"`; INT-1, WP7). A `"walk"` disagreement is a WARNING and counts against `is_reliable`; `"stable end"` evidence is INCOMPLETE and gives no verdict (C11, WP10: `word_agrees` None, INFO; `verified` reads only the evidence with a verdict). Exact-itinerary disagreement is INFO only, because a registered image endpoint can sit exactly on a closed boundary.
  - *Symbols.* An active class uses its session letter; inert classes take the SEPARATE series `u, v, w, x, y, z, uu, …` (`inert_letters`, `letter(i, inert=True)`), disjoint by construction from the active `a..t, aa, …` (`letter(i)`, one bijective numeral over two digit sets, no skipping, SIMP-6; the session `BridgeAlphabet` stays active-only); the alphabet is CLOSED under the word map (WP7, C9): every pair of a walk is the class of one piece of `f(B)`, so a word naming a class outside the alphabet adds it -- walked in turn, lettered by the session (`symbolic_dynamics(letter_for=BridgeAlphabet.letter_for)`; an inert one continues the inert series), with `ClassDynamics.named_by` = the class whose word first named it; `SymbolicDynamics.table` is the closed alphabet (seed first), `session.bridge_classes()` stays the seed (D2). A class some registered bridge spans (the evidence table `minimal.classes`) is a copy of its entry; a pair NO computed bridge spans is a class all the same (D11, author 2026-10-08: "we do not need computed bridges to find words"): a member-less entry, active by the no-evidence convention, walked from its elements' landings and flagged "no computed bridge yet" (`BridgeClassEntry.spanned` False, in `describe()`), informational only -- it never makes `is_reliable` False (only a member-less class landing on a singleton, which cannot walk, stays unresolved). The closure runs until no word names a new pair (element pairs are finite) and is a function of the dual graph alone. No law case names such a pair; the deep runs do (`p3_15`, `p3_6_blasts` 23 -> 43 classes, 20 flagged; `p3_16` 27 -> 49; nested with 6 inner blasts 27 -> 47; all reliable), k=2.8 at 8 blasts 15 -> 23 (3 flagged) is reliable since the walk runs between the landing spans (WP9b; at 9+ blasts one evidence disagreement remains, INT-11). Registered evidence never adds a symbol (a class outside the closed table is named by its label). Directions are ALWAYS shown, inert included: k=10 reads `a -> a u^-1 a^-1` (the walk crosses `u = {L_1, L_3}` against its anchor-outward orientation). Pairs falling into one element are loops: dropped from the word, kept in `loops`. A pair on one branch with two sides is flagged (`cross_side`) and logged, never asserted; a pair across two branches is never flagged (D4).
  - *Refinement* (`refine`). Occurrences come ONLY from the walked/trellis itineraries of ALL classes, never from registered images. A class whose symbol occurs with two or more distinct iterated pairs splits into `a_1, a_2, …` anchor outward (`RefinedClass`); every refined child inherits the parent's word rewritten in refined symbols — k=10: `a_1 = (R_1^1, R_3^3)`, `a_2 = (R_1^3, R_3^1)`, `a_1 -> a_1 u^-1 a_2^-1` AND `a_2 -> a_1 u^-1 a_2^-1`. Members are matched to refined children by their OWN endpoint owners (`match_members`; the empty-stretch cut makes every image crossing belong to the element of the edge the walk crosses there, so the fixtures match every member); an unmatched member goes to `unmatched_members` at INFO (`plot_bridges_by_class` draws one in its parent letter's own palette slot, labelled "(unmatched)"). A refined class never changes `BridgeClass` identity.
  - *Transition graph / matrix* (`transition_graph`, `transition_matrix`; `refined=True` by default). Nodes are the refined ACTIVE symbols (of the closed alphabet, so every edge target is a node), one edge per token with `weight` = multiplicity; INERT classes are not in the graph or the matrix (author, 2026-09-23: they contribute nothing to the dynamics, their symbols stay visible in the words; a token naming one is skipped; an inert class whose word names a NON-inert class warns, an inert class mapping onto inert classes (the next branch's, on a period-k orbit) is silent (PK-8)). k=10: nodes `a_1, a_2`, matrix `[[1,1],[1,1]]`. No spectral radius is computed or shown (author, 2026-09-23: removed until its meaning for the trellis is settled).
  - *Fixture facts* (letters by cdist since 2026-09-21). k=2.8 two blasts: `a = {R_1,R_5}` (the anchor class), `b = {R_3,R_5}`, `c = {R_1,R_3}`, `u = {L_1,L_3}`; `a -> a u^-1 b^-1`, `b -> c`, `c -> a u^-1 a^-1`; `a` refines into `a_1 = (R_1^1, R_5^3)`, `a_2 = (R_1^3, R_5^1)` and every member matches a child; matrix over `(a, b, c)` = `[[1,1,0],[0,0,1],[2,0,0]]`. k=2.8 one blast: the single active class is singleton-to-singleton, resolved via the trellis path, word `a u^-1 v^-1`; the inert classes are trivial loops. `TangleSession.symbolic_dynamics()` is a stage of `TangleSession.topology()`, one object per `(generation, selection, pips)`.

## Core Library Architecture (`src/tanglepack/`)

Three subpackages plus examples. **Dependency rule: `numerics` and `topology` never import `loom`** (loom sits on top and weaves the other two together).

- `numerics/` — the numerical engine: maps, fixed points, manifold growth, crossing detection, bridges, the intersection registry.
- `topology/` — combinatorial structures over the registry: the `Trellis` snapshot, strong pips, pseudoneighbors, holes, the stable partition, the planar `Arrangement` of regions, bridge classes, the minimal trellis and dual graph, and the symbolic dynamics (element names, dual-graph walks, words).
- `loom/` — cross-layer algorithms that read topology and act on numerics: `TangleSession`, resonance zones, blasting.
- `examples/henon.py` — the one Hénon map definition (`henon_map(k, b)`, `henon_map_inverse`, `henon_jacobian`, `saddle_guesses`) used by tests and scripts (the notebooks still carry their own copies; see the plan's Deferred list); `examples/henon_cases.py` — the shared higher-period recipes `build_period3()` / `build_nested()` / `build_heteroclinic()` (period 3 at 16 / 10 steps: four `W^u(p3) x W^s(p1)` crossings, two in the trellis, WP9) → `TangleBuild` (session, fixed points outermost first — constructed in that order, so p1 is `A` and tangle 0, NEST-6 —, pips, title, slug; each ends at `session.topology()`, the pips carried by the session through every blast, no repin), used by the figure scripts and `tests/test_higher_period_cartoon.py`; a nested build's slug encodes non-default blast counts (`nested_p1_p3_outer5_inner1`; the defaults keep `nested_p1_p3` / `heteroclinic_p1_p3`, API-7, WP11). Period 3 at 13 unstable steps is CLOSED (`a -> b -> c -> a u^-1 w^-1`, no image bridges; blasting changes nothing); the `check_holes_share_bridge_side` trip at 15–16 steps and 6+ blasts is fixed (2026-10-02: a propagated hole's side is read on its image sub-arc, a direct hole's from its crossing signs), and past the reference switch (BCG-4) the word of an image-bridge class names the class of ITS image, a pair no computed bridge spans, which is a class flagged "no computed bridge yet" (D11, WP8b), so those runs are reliable; the default stays at 13 steps, before the switch. Nested needs two outer blasts for every class to resolve.

**Symbolic-itinerary figures.** `scripts/symbolic_figures.py` `draw_panels` writes six panels per case into `figures/henon_symbolic_itineraries/<slug>/` — `trellis`, `partitions`, `cartoon`, `itineraries`, `transitions`, `transitions_refined` — each as `.png`, `.svg` and `.fig.pickle` (networkx's curved edge labels are frozen into plain `Text` before pickling). The cartoon panel is `shape="circle"`. The trellis panel draws ONLY the minimal trellis's bridges (`plot_bridges_by_class(..., bridge_ids=minimal.kept_bridge_ids)`): every blast child is a class member, so an unfiltered plot grows with each blast even though the minimal trellis does not (nested: 16 kept bridges from 2 to 5 outer blasts while the trellis goes 38 -> 72).

The entry point for programmatic use is `TangleSession` (a facade over one `TangleWorkbench`, caching one `Trellis` per fixed-point selection and delegating unknown attributes to the workbench):

```python
import numpy as np, tanglepack
from tanglepack.examples.henon import henon_map, henon_map_inverse, henon_jacobian, saddle_guesses

session = tanglepack.TangleSession(henon_map(10), henon_map_inverse(10), henon_jacobian(10),
                                   area_cutoff=1e-4)   # default 1e-7 (converged, ~10x the points); also max_points_per_step (2,000,000; None = off)
fp = session.construct_fixed_point(saddle_guesses(10, 1)["saddle"])
session.orient_eigenvectors(fp, {"unstable": np.array([-1, 0]), "stable": np.array([0, 1])})
session.initialize_both_manifolds(fp)
session.grow_n_times(fp, "unstable", num_iterations=8)   # fixed count: no notion of escape, only the point budget
session.grow_until_turnaround(fp, "stable")
session.compute_intersections([fp])          # registers anchors + crossings, infers iterates
session.trim_stable_manifolds(fp)
session.create_bridges(fp)                   # bridges keyed by BridgeId
session.classify_strong_pips()               # default pip, remembered across generations
A = session.arrangement()                    # faces -> Region objects
topo = session.topology()                    # one recompute: pseudoneighbors, holes, partition from the pip ...
topo.classes                                 # = session.bridge_classes(): the lettered alphabet
topo.minimal                                 # hole bridges + images of the active ones
topo.iterated                                # homotopy partition cut by the minimal trellis's image bridges
topo.dual_graph                              # StableNodes / FaceNodes over its sparse arrangement
topo.dynamics                                # itineraries, words, refined classes, transition graph
```

**Data model — how a manifold is stored.** Points form two simultaneous doubly-linked lists inside `Point`: the *geometric* list (`forward`/`backward`, order along the curve) and the *iterate* list (`next_iterate`/`prev_iterate`, which point maps to which). `BranchPoint` is the root anchored at the periodic point. `BaseManifold` holds `root`/`tail` (setters bump `version`) and one `_collect` walker behind every getter; bridges memoise their point arrays (read-only).

**Manifold key.** `ManifoldKey = (FixedPoint, Stability, orbit_index, branch_index)`. Every `BaseManifold` and `Bridge` carries its key (required at construction); `workbench.register_manifold(key, manifold)` asserts they agree. `FixedPoint.advance_key(key, n)` is the ONE rule for what n map steps do to a key (orbit index advances; the branch flips only when the orbit index wraps and the point has inversion). `FixedPoint.num_branches` is 2 iff inversion (`k_value == 2 * period`); `per_step_beta(stability)` is the per-map-step canonical-distance factor `|λ|^(1/period)` (a branch return is `k_value` steps and costs `λ^num_branches`); `branch_cycle(stability)` lists the `k_value` keys in forward-map order. `period` is always the MINIMAL period: `construct_fixed_point` raises `ValueError` on an orbit that repeats with a proper divisor of the requested period, and `k_value = 2 * period` is never a period to request.

**Invariants the code asserts (keep them):** cdist non-decreasing along a manifold; every registered crossing is unstable × stable; every bridge is an arc between consecutive crossings on one unstable branch; holes of one origin share `bridge_side` (parity-flipped under an orientation-reversing map); a hole bridge whose crossings share a stable branch has alternating crossing signs (one row at both ends); exactly one partition element owns each crossing per side (by id at a boundary, by EXACT cdist elsewhere: boundaries are registry floats, asserted; dedup is relative (`DEDUP_RTOL`); the topology reads no absolute cdist slack: anchors by identity (`is_anchor`), ownership and containment exact, scaled cdists carry their RELATIVE error (`SCALING_RTOL`, `collision_rtol`); `cdist_tol` is only the absolute slack of degenerate bridge cuts and polyline clipping, C15, WP11); the iterate table is a partial bijection; `image_of(region)` preserves area; an image pair lies in at most one bridge's image chain (the map is a bijection); every itinerary has even length and splits into disjoint pairs, same-side on one branch (`trellis_itinerary` asserts the length; a cross-side pair on one branch is flagged and logged, not asserted); refined classes never change `BridgeClass` identity.

**Point budget (a resource guard, not an invariant).** `PointBudgetExceeded` is an exception type, never an `assert`, and never feeds `is_reliable` or the provisional flags. It is raised mid-step and the state is NOT resumable (a growth chain partly mapped and under-refined; a blasted bridge's points linked to a half-refined image while `iterated` stays False, so `iterate_bridge` refuses that bridge again): rebuild with fewer steps, a stop condition (`grow_until_bounded`), a coarser `area_cutoff` or a larger budget. The generation still advances. `blast_zone` never swallows it: it re-raises with the zone, step and bridge appended (`exc.blast_context`, a declared attribute, None outside a blast; `MaxIterationsReached` and `TURNAROUND_LOG_STRETCH` are exported, API-3, WP11). Its own `max_points` budget is the clean stop (between iterations, resumable).

**Generation counter.** `IntersectionRegistry.generation` bumps on every registry mutation; `TangleWorkbench.generation` is a monotone token over its own mutations, the registry generation and every manifold's `version`. A `Trellis` records `_built_generation`; `TangleSession.trellis()` / `arrangement()` rebuild when it differs, and `TangleSession.topology()` rebuilds when the generation or the selection's strong pips differ. There is no manual invalidation.

**Intersection detection.** `compute_intersections` bulk-loads all manifold segments into the two rtrees, one per stability (`Tangle.add_manifolds`; each unstable segment is queried against the stable index); `iterate_bridge` registers image bridges query-only (a bridge is unstable, so everything it can cross is stable and already indexed). Crossings are resolved once, registered in the registry, then bridges are cut at those exact crossings. The iterate table is EXACT (WP2): y = M(x) iff y is on the advanced branches and both its brackets (the node cdists either side of it on each curve) meet x's carried one step by the manifolds' `stretch_param`, uniquely, and the real map confirms it within the image of x's unstable segment plus y's own (one batched call per pass); it runs in `compute_intersections`, in every `iterate_bridge` and at the end of every `blast_zone`, so the topology only looks links up. How well they are resolved is set by the machine's `area_cutoff`: the library default is 1e-7 since 2026-10-07 (was 1e-4; the stress campaign's E4 found 1e-7 the cheapest cutoff converged on every case), and a recipe tuned at 1e-4 passes it explicitly. No same-stability pair is ever formed (one rtree per stability, WP10); near-parallel pairs are logged and discarded. Registry ids survive `compute_intersections(preserve_ids=True)`, and they are REPRODUCIBLE (INT-7, WP8): crossings are registered along each unstable branch in unstable-cdist order, never in the iteration order of a set of segment ids (`Tangle._ids` is a process-wide counter), so two builds of one case in one process number them alike. `compute_intersections` REPLACES `workbench.intersection_registry` (unless `reset=False`) and returns the new one: re-fetch the registry after every call, a held reference goes stale (logged at DEBUG). **Resolution guards** (2026-10-07, flags only): every detected crossing carries `resolution_ratio = min(l_u, l_s) * |sin| / max(h_u, h_s)` (chord deviations, floor `1e-8 * min(l)`; anchors/synthetics None); below `resolution_ratio_threshold` (3) it cannot be told from polygon noise. `report_resolution` logs ONE WARNING for new unresolved crossings and one for new same-stability polyline crossings in the padded crossing box (INFO outside it), each finding once, on the `TangleWorkbench` logger; it runs at the end of top-level `compute_intersections(diagnose=True)` (growth loops pass False; `grow_until` reports once when its predicate holds) and once per `blast_zone(diagnose=True)` call, which only COUNTS the same-stability hits its new image bridges take part in and remembers none (C5, PERF-1, WP10). Neither flag feeds `is_reliable` or the provisional flags (a category-(iii) resolution signal).

## Coding Style

- **Docstrings**: Google-style with `Args:`, `Returns:`, `Raises:`, and `Note:` sections. Write them for every public class, `__init__`, and method. One-sentence private helper docstrings are fine.
- **Dev Notes**: Module-level `"""Dev Notes: ..."""` blocks are the preferred place for longer-term design questions and open issues — not inline TODOs scattered through methods.
- **Type hints**: Always annotate function signatures. Use `Literal["unstable", "stable"]` for the stability parameter. Use `Optional[X]` and `NDArray[np.float64]` from `numpy.typing` for array return types.
- **imports**: `from __future__ import annotations` at the top of every file that uses forward references. Group: stdlib, then numpy/scipy, then local `.` imports.
- **Naming**: `PascalCase` for classes, `snake_case` for everything else. `_single_leading_underscore` for private methods.
- **Avoid bare print statements**: Use `logging` (the module already configures a `NullHandler` logger in `ManifoldMachine.py`). Debug output that ends up in production code is a recurring issue — prefer `logger.debug(...)`.
- **Comments**: Sparse inline comments only when the invariant is non-obvious. Do not leave blocks of commented-out old code in committed files — the dev notes pattern or git history is the right place for those.
- **Assertions**: Used to check invariants (e.g., cdist ordering after merge). Keep them; they are the primary correctness guard here.
